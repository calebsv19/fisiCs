# Explicit owner workflows and bound controls

This opt-in P11.3/P11.4 entrypoint consumes the exact P11.1 bindings. It reuses
the Phase10 builder, ABI probe, source preparation and independent references.
Only explicit test wiring is added; compiler/solver/reader source stays unchanged.

```sh
python3 -B healthy.py --binding /absolute/P11.1-binding --out /absolute/fresh-native-root
python3 -B controls.py --healthy /absolute/fresh-native-root --out /absolute/fresh-controls-root
```

`healthy.py` builds fresh contained matching Clang/released fisiCs profiles and
qualifies3 owner workflows/12 healthy profile outcomes. Selected strict reports
are separate from deliberately blocked raw-body reports. Native JSON is checked
against the original independent references and exact matched-profile parity.

`controls.py` executes only the12 logical controls/48 profile expectations in the
binding:39 applicable and9 explicit physical-receipt N/A cells. The healthy rows
are reused without relabeling as new runs. Wrong dimensions must compile as legal
C before units/physical rejection; numerical defects must compile and reach their
independent numerical detectors. Copy/header/source and receipt inputs restore
exactly, with successful fresh execution/recheck. All mutations are task-local.

Commands, reports, source identities and failed attempts are retained. The compiler
process guard is1; no automatic Make target, default overlay or runtime
instrumentation is added. Timings are operational logs, not cost qualification.
P11.5 budgets and P11.6 review/adoption remain outside these entrypoints. Native
builds/resume state are disposable after both consumers finish; rebuild fresh
for later native work. Stop before P11.5, adoption, installation or release.

Freshness witnesses use only the public portability macros and the exact bound
scalar energy/mechanical-strain contract. The frozen P11.1 full-header witness
imports unrelated unsupported record/pointer interfaces; its refusal remains
retained. Per-family fixture-amendment.json records original/effective bytes;
no checker, model or owner header was changed. The successful source bytes and
reports, not the old full-header recipe, are the effective P11.4 freshness input.

`controls.py --resume` may resume verified completed per-family controls only in
its same unfinished task root. `verify.py` replays raw numerical/diagnostic/report
and exact-restore evidence without solver/compiler execution and supports
losslessly compressed retained reports/logs. Native build state is retired after
all consumers finish; P11.5 must prepare fresh native products when needed.

P11.5 uses two further opt-in entrypoints; run each with a fresh absolute output:

```sh
python3 -B iteration.py --binding /absolute/P11.1-binding --amendment /absolute/P11.4-effective-freshness.json --out /absolute/fresh-iteration
python3 -B cost.py --iteration /absolute/fresh-iteration --binding /absolute/P11.1-binding --out /absolute/fresh-cost-window
python3 -B verify_iteration_cost.py --iteration /absolute/fresh-iteration --cost /absolute/fresh-cost-window --binding /absolute/P11.1-binding --out /absolute/new-replay.json
```

Iteration checks source/include/policy/catalog invalidation, unchanged receipt
reuse, regeneration, exact restoration, missing/corrupt receipts, failed fresh
generations and occupied output refusal. All changes stay in fixture copies.
Cost checks reuse the maintained Phase10 runner with its existing pinned
preprocessor and guard1 adaptations. Six scalar inputs run base/units/physical
compilation plus strict reports; three receipt pairs run fresh check processes.
There are 270 executions (243 measured, 27 warmups), with nine measured samples
per mode/workload. The original 1.5x+0.05s/8MiB matched limits and separate
1s/256MiB report limits remain unchanged. Preprocessing is outside compile
timing. Native and full owner-TU costs are reused only with their unchanged
source/tool/policy/workload identities; new scalar timings are not solver costs.

The replay command reads raw timings/logs, exact medians and report counts; it
supports lossless gzip reports/logs. No default build hook, runtime instrument,
new compiler inference, adoption, installation or release is part of this lane.
P11.6 freezes a finite source/evidence review candidate; adoption remains a
separate decision. Rebuild native products fresh when a native consumer needs them.

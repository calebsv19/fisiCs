## Signal And Heartbeat Payloads

Protocol-v1 signal payload:

```text
byte 0      instance
byte 1      sequence
byte 2      source validity
byte 3      reserved, required zero
bytes 4..   big-endian value using the semantic type's width
remaining   reserved, required zero
```

Protocol-v1 heartbeat payload:

```text
byte 0      protocol version
bytes 1..4  session ID, u32 big-endian
byte 5      health flags
byte 6      active fault count
byte 7      reserved, required zero
```

Pass 3 has separate quality, freshness, and usability fields. Protocol v1 has
one source-validity field, so Pass 6 maps a sample to `VALID` only when the
source record is valid, fresh, and usable; otherwise it transmits `INVALID`.
Receiver freshness is still recomputed from delivery time.

## Session Behavior

The modeled producer sessions are explicit authored simulation identities for
BENCH_A and BENCH_C. Heartbeats occur once per simulated second with a
2.5-second receiver timeout.

The receiver behavior is:

- first heartbeat starts the source session;
- repeated same-session heartbeat refreshes liveness;
- changed session ID clears that source's sequence and latest-good state;
- sequence zero is then accepted in the new session;
- signal traffic without a live session is rejected;
- same-session recovery after timeout retains sequence state; and
- unsupported heartbeat protocol versions are rejected.

An explicit startup delay ensures both initial heartbeats complete before the
first signal release. The nominal projection therefore has zero pre-session
signal rejections.

## Residual Protocol-v1 Assumption

The heartbeat carries session identity, but an individual signal payload does
not. A receiver can reset its sequence state when a new heartbeat arrives, but
it cannot inspect a later signal and prove which session created that signal.

Pass 6 therefore makes this producer rule explicit:

```text
On restart, flush pending signal frames before transmitting the new-session heartbeat.
```

Without that rule, delayed old-session bytes can be accepted under the current
session. The conformance artifact demonstrates this limitation instead of
hiding it. This is a bounded protocol-v1 operational precondition, not a claim
of cryptographic or per-frame session binding.
